## 5. LoRA dataset: current state and correct definition

### What exists (LIVE-MEASURED from `LoRAData/final/`)

- 6,874 rows (train 4,688 / dev 849 / test 1,337), Gemma-4 template, assistant-only masks, audits pass.
- **Family mix is mostly not SWE work:** `dag` 4,565 (66%), `systems` 1,514 (22%), `agent` 716 (10%), `exec` 33, `pyedit` 46.
- **72% of rows (4,954) are derived from the 129 public tasks** (fastapi, rich, requests, httpx); the remainder is 1,920 synthetic DAG puzzles.
- p95 length ≈ 2.2k tokens. Real v6 trajectories: median 12 steps, peak context 11.5k (max 22.1k) tokens, 10/23 tasks cross the 14,336-token compaction threshold.

### What the grader rewards

- Hidden set: about 120 tasks, **curated from private repositories** (DATASET_DESCRIPTION.md line 86). It does not share the four public repos.
- `resolved` = hidden `test_patch` applied, pytest exits 0, ≥1 pass, 0 failures/errors. Test and config edits are stripped. Only library-code diffs count.
- Time cap ≈ 5 min/task, 40 calls, 32k context, compaction at 14,336 tokens, thinking budget 4,096.

So the adapter must generalize to **unseen repos**, inside this exact tool protocol and budget. The current set teaches graph puzzles on the public repos, which is the wrong target and also contaminates the only local eval we have.

### Definition (PROPOSED, needs your sign-off before building)

1. **Unit = one full agent trajectory** in the exact ADK/harness format: system prompt, task prompt, thinking blocks, calls to the 9 tools + `run_skill_script`, tool observations, ending in `submit_patch`. Rendered with the Gemma-4 template, `enable_thinking`, loss on assistant tokens only.
2. **Sources = repo-disjoint permissive Python repos** (not fastapi, rich, requests, httpx): real merged PRs with a bug fix plus tests (SWE-bench-style issue / patch / FAIL_TO_PASS), plus seeded-defect tasks on the same repos for volume. Record license and commit per repo.
3. **Trajectory generator = our own harness**, run in the Docker sandbox with the v7 agent: (a) E4B self-rollouts at temperature, keeping only resolved runs (rejection-sampling fine-tuning, which needs no third-party licence check), and (b) optionally a stronger teacher, once Q5 (provider terms) is cleared.
4. **Acceptance gate = the harness's own Phase-2 verification** (`resolved=True` with the hidden-style test patch). Not the `repo_eval` syntax gate, which is known to pass everything.
5. **Shape targets from measured failures:** reproduce-in-`/tmp` before edit; small `edit_file` payloads; `fix_edit` rescue after an edit error; a targeted test after each edit; submit only on green; finish ≤ 40 calls / ≤ 5 min; stay under 14k context.
6. **Splits:** train/dev by repo (never by task). The public 129 stay **evaluation only**. Keep the existing `dag`/`systems` rows out of the core set; at most a small ablation arm.
7. **Manifest per row:** repo, license, commit, task id, generator, model, resolved receipt, tokens, tool-call count, wall time.

### MLX vs CUDA path

- Train on CUDA (Kaggle L4×4) on the QAT bf16 source; target `q,k,v,o,gate,up,down` across all 42 layers (config read today: 42 layers, hidden 2560, 8 heads / 2 KV heads, head_dim 256, sliding window 512, 5:1 sliding:full). Rank ≤ 32 to start.
- Ship as PEFT `adapters/main_lora` for vLLM. **Missing:** a PEFT→MLX adapter converter plus a parity check (same prompts, logit/token agreement on MLX+adapter vs vLLM+adapter) so local scores mean something.
- Budget: AGENTS.md cites ~29% LoRA slowdown. Re-measure on L4 before choosing `max_time_minutes`.
