# v13_orchestrator: Active Orchestrator + Isolated `/tmp/ws` Subagents

Combines the `v12_merged` recurrent typed IR, unlocked zero-BM25 graph walk, non-library candidate filter, pre-pytest import/symbol guard, and blocking `verify` with an active orchestrator architecture:

- **Active Orchestrator (`agent.yaml`, `prompts/system.md`):** Holds `run_command`, `get_status`, `submit_patch`, `skills/semdag`, and `agent_tool` (`editor_1`, `editor_2`). Never edits `/workspace` directly. Runs tactical audit (`repo_eval.py` + baseline `pytest`), spawns isolated workspaces via `workspace_mgr.py`, applies the winning patch, runs adversarial verification (`pytest` + `repo_eval.py --verify`), and allows at most 1 final retry before `submit_patch`.
- **Isolated Subagents (`sub_agents/editor_1.yaml`, `editor_2.yaml`):** Run at `temperature: 0.0` (`thinking_budget: 4096`, `max_output_tokens: 16384`) strictly inside `/tmp/ws_1` and `/tmp/ws_2` with zero cross-talk. Guided by deterministic `/tmp/ws_<slot>/Agents.md` generated by `workspace_mgr.py`.
- **Deterministic Workspace Manager (`skills/semdag/scripts/workspace_mgr.py`):** `--spawn`, `--collect`, `--apply`, `--reset` in pure Python stdlib.


## Workspace isolation (2026-11-22)

Slot files are independent copies, not hardlinks. Editing a slot cannot change the central repository or another slot before `--apply`. Slot names and target paths are validated; symlinks are refused and only unprotected Python changes are collected. Workspaces use the subprocess sandbox's temporary directory. Literal `/tmp/ws_<slot>` skill arguments resolve to that directory and a missing explicit workspace fails instead of falling back to central code.

Host regressions: `PYTHONDONTWRITEBYTECODE=1 .venv-harness/bin/python -m pytest tests/test_v13_workspace.py`. Tests cover in-place writes, collect/apply, sibling preservation, protected files, invalid paths, symlinks and subprocess path resolution. These are component tests, not a task-resolution score.

Runtime testing uses Gemma E4B only under macOS Seatbelt with the official subprocess backend; no Docker. External-task grading must first reject the empty patch and accept the reference fix. See `Tools/local/qualify_v13.py` and the host run report under `reports/v13_qualification_2026-11-22/` (local artifacts).

The workspace manager accepts normal argument lists and one shell-quoted packed command string. The skill manual documents its run_skill_script route; editors must not be dispatched before a successful spawn. This repairs the malformed-call failure observed in the first external E4B run.


## Stage 1 native edit transactions (2026-11-23)

`skills/semdag/scripts/edit_tx.py` combines preparation and finalization while binding edits to task/slot/file/span hashes. Prepare returns numbered code and a single-use handle; edit returns a new handle; finalize verifies an independent copy before atomic central apply, then verifies central tests and the diff. Stale, off-assignment, unknown and replayed handles are refused. Managed legacy apply uses the same finalization gate; managed range writes require an edit handle instead of trusting old coordinates.

Source writes preserve supported UTF-8/BOM, LF/CRLF, final-newline state and file mode. Unsupported encodings fail unchanged. Atomic ephemeral metadata can be lost on a crash; source hashes make lost/old checkpoints fail closed. Source writes are fsynced. These are helper-path checks, not full filesystem containment: direct shell writes remain a broader capability.

Use `run_skill_script` with `skill_name: semdag`, `file_path: scripts/edit_tx.py`, and `args`:

- Prepare: `--prepare ISSUE --remaining SECONDS_FROM_GET_STATUS --slot 1`.
- Edit: `--edit HANDLE --slot 1 --text REPLACEMENT`.
- Narrow/read: `--view HANDLE --slot 1 --lines A-B`.
- Finalize: `--finalize HANDLE --slot 1`.

Always pass separate strings in `args`, with code as one string. Official required tool-envelope keys remain mandatory; no host rewrite supplies missing keys. Existing editor count/ambiguity dispatch and one-final-retry policy remain for the Stage 1 comparison; subagent policy tuning is deferred.

## Role-bound action policy (2026-11-23)

Root and both editors no longer receive `run_command`, raw edit/write/read tools, or executable implementation helper scripts. Each agent loads a separate `semdag` skill from a directory whose basename matches that canonical name:

- Root: `skills/semdag`, entry `scripts/run.py`, native actions prepare/finalize/status.
- Editor 1: `skills/editor_1/semdag`, same entry path, actions view/edit/status bound to slot 1.
- Editor 2: `skills/editor_2/semdag`, same entry path, actions view/edit/status bound to slot 2.

Static entry bindings cannot be changed by user flags. Dependencies are readable `assets/engine/*.py`; SDK script lookup exposes only `run.py`. Use `Tools/local/sync_v13_role_assets.py --check` to detect dependency drift, or run it without --check after editing the canonical root engine. Actual compiled-toolset subprocess tests cover wrong-role calls, cross-slot access, helper/asset/traversal execution denial, missing official keys and legitimate prepare/edit/finalize with both editors. Symlinked sandbox paths are canonicalized before assignment identity comparison.

This restricts registered action surfaces; it does not stop every unprepared agent_tool dispatch or empty submit, make patched library code safe to execute, or provide full host filesystem confinement. E4B, four-minute/default-token budgets and dispatch count/ambiguity/retry rules remain unchanged. No numeric editor timing thresholds have been chosen.
