# v13_orchestrator: Active Orchestrator + Isolated `/tmp/ws` Subagents

Combines the `v12_merged` recurrent typed IR, unlocked zero-BM25 graph walk, non-library candidate filter, pre-pytest import/symbol guard, and blocking `verify` with an active orchestrator architecture:

- **Active Orchestrator (`agent.yaml`, `prompts/system.md`):** Holds `run_command`, `get_status`, `submit_patch`, `skills/semdag`, and `agent_tool` (`editor_1`, `editor_2`). Never edits `/workspace` directly. Runs tactical audit (`repo_eval.py` + baseline `pytest`), spawns isolated workspaces via `workspace_mgr.py`, applies the winning patch, runs adversarial verification (`pytest` + `repo_eval.py --verify`), and allows at most 1 final retry before `submit_patch`.
- **Isolated Subagents (`sub_agents/editor_1.yaml`, `editor_2.yaml`):** Run at `temperature: 0.0` (`thinking_budget: 4096`, `max_output_tokens: 16384`) strictly inside `/tmp/ws_1` and `/tmp/ws_2` with zero cross-talk. Guided by deterministic `/tmp/ws_<slot>/Agents.md` generated by `workspace_mgr.py`.
- **Deterministic Workspace Manager (`skills/semdag/scripts/workspace_mgr.py`):** `--spawn`, `--collect`, `--apply`, `--reset` in pure Python stdlib.


## Workspace isolation (2026-11-22)

Slot files are independent copies, not hardlinks. Editing a slot cannot change the central repository or another slot before `--apply`. Slot names and target paths are validated; symlinks are refused and only unprotected Python changes are collected. Workspaces use the subprocess sandbox's temporary directory. Literal `/tmp/ws_<slot>` skill arguments resolve to that directory and a missing explicit workspace fails instead of falling back to central code.

Host regressions: `PYTHONDONTWRITEBYTECODE=1 .venv-harness/bin/python -m pytest tests/test_v13_workspace.py`. Tests cover in-place writes, collect/apply, sibling preservation, protected files, invalid paths, symlinks and subprocess path resolution. These are component tests, not a task-resolution score.

Runtime testing uses Gemma E4B only under macOS Seatbelt with the official subprocess backend; no Docker. External-task grading must first reject the empty patch and accept the reference fix. See `Tools/local/qualify_v13.py` and the host run report under `reports/v13_qualification_2026-11-22/` (local artifacts).

The workspace manager accepts normal argument lists and one shell-quoted packed command string. The skill manual documents its run_skill_script route; editors must not be dispatched before a successful spawn. This repairs the malformed-call failure observed in the first external E4B run.


## Stage 1 native edit transactions (2026-11-23)

`skills/semdag/scripts/edit_tx.py` combines preparation and finalization while binding edits to task/slot/file/span hashes. Prepare returns numbered code and a single-use handle; edit returns a new handle; finalize verifies an independent copy before atomic central apply, then verifies central tests and the diff. Stale, off-assignment, unknown and replayed handles are refused. Managed legacy apply uses the same finalization gate; managed range writes require an edit handle instead of trusting old coordinates.

Source writes preserve supported UTF-8/BOM, LF/CRLF, final-newline state and file mode. Unsupported encodings fail unchanged. Atomic ephemeral metadata can be lost on a crash; source hashes make lost/old checkpoints fail closed. Source writes are fsynced. These are helper-path checks, not full filesystem containment: direct shell writes remain a broader capability.

Use `run_skill_script` with `skill_name: semdag`, `file_path: scripts/edit_tx.py`, and `args`:

- Prepare: `--prepare ISSUE --remaining SECONDS_FROM_GET_STATUS --slot 1`.
- Edit: `--edit HANDLE --slot 1 --text REPLACEMENT`.
- Narrow/read: `--view HANDLE --slot 1 --lines A-B`.
- Finalize: `--finalize HANDLE --slot 1`.

Always pass separate strings in `args`, with code as one string. Official required tool-envelope keys remain mandatory; no host rewrite supplies missing keys. Existing editor count/ambiguity dispatch and one-final-retry policy remain for the Stage 1 comparison; subagent policy tuning is deferred.

## Role-bound action policy (2026-11-23)

Root and both editors no longer receive `run_command`, raw edit/write/read tools, or executable implementation helper scripts. Each agent loads a separate `semdag` skill from a directory whose basename matches that canonical name:

- Root: `skills/semdag`, entry `scripts/run.py`, native actions prepare/finalize/status.
- Editor 1: `skills/editor_1/semdag`, same entry path, actions view/edit/status bound to slot 1.
- Editor 2: `skills/editor_2/semdag`, same entry path, actions view/edit/status bound to slot 2.

Static entry bindings cannot be changed by user flags. Dependencies are readable `assets/engine/*.py`; SDK script lookup exposes only `run.py`. Use `Tools/local/sync_v13_role_assets.py --check` to detect dependency drift, or run it without --check after editing the canonical root engine. Actual compiled-toolset subprocess tests cover wrong-role calls, cross-slot access, helper/asset/traversal execution denial, missing official keys and legitimate prepare/edit/finalize with both editors. Symlinked sandbox paths are canonicalized before assignment identity comparison.

This restricts registered action surfaces; it does not stop every unprepared agent_tool dispatch or empty submit, make patched library code safe to execute, or provide full host filesystem confinement. E4B, four-minute/default-token budgets and dispatch count/ambiguity/retry rules remain unchanged. No numeric editor timing thresholds have been chosen.

Final role-policy verification: 272 full host tests and official validation pass, including actual SDK denied calls and successful lifecycles for both editor roles. Live E4B trials remain 0/1 each with empty patches (241.58 s timeout and 84.82 s failed grading). No successful native preparation/edit/apply in those live runs; no task-quality promotion or timing-threshold tuning. See [role-policy report](../../docs/runs/v13_ROLE_POLICY_2026-11-23.md).


## Typed SDK argument ABI and protocol diagnosis (2026-11-23)

The SDK inserts `--`; native code parses the explicit action/data production without inventing missing values. Forms are prepare ISSUE SECONDS SLOT, edit HANDLE CODE, view HANDLE A-B, finalize HANDLE SLOT and status [SLOT]. Legacy flag grammar remains supported. Do not mix args/short_options with this preferred ABI; required outer skill_name/file_path still must be correct.

Read-only probes found that the local CT and MLX templates match, and args.anyOf renders an empty native type while positional_args renders array/string. Both simple raw/chat probes pass. A captured full-context raw replay nevertheless generates the nonexistent dask skill; greedy replay does too. Thus the parser is not proven to be the cause of semantic routing errors. No SDK/template patch or model-output cleanup was added.

Discovery policy now aligns with the SDK's appended model-facing MUST-load instruction: root lists the registered skill inventory, loads its returned name, then budgets and prepares. Editors load their role skill. This is an instruction/lifecycle alignment, not a claim that the SDK enforces load-before-execute. Unprepared native status now gives root a prepare instruction and editors an EDIT_FAILED instruction.

Exact request capture is optional host-only telemetry, mode 0600, bodies only/no headers; task/model bodies stay local. Only verified public parser/template research was ingested into the host Edge store, never task/code/model artifacts. Source manifests and raw receipts are under reports/v13_protocol_2026-11-23/.


## Assignment-bound verification repair

Preparations now have independent cache namespaces carried into finalization, including correct alternative-site checks/anchor metadata. A BM25 guess retains a whole-function scope; trusted exact anchors still receive loop-locus constraints. Root may replace only an unchanged prepared assignment; pending changes are preserved. Each issued handle is durably recorded in the workspace marker before atomic state replacement, preventing older metadata from reviving a revoked read-only view or assignment.

Candidates are compiled without execution before writing, catching contextual syntax such as return/break outside a valid scope that ast.parse alone accepts. Editors should narrow to a complete changed block rather than replace a whole function with only its body.

Regression suite: 296 passed. The latest fixed-source benchmark still reduces modeled control steps 9→4 with identical output, but native median overhead is +15.44%, exceeding the original 10% timing gate. That performance gate is not relaxed or claimed passed; these correctness repairs remain experimental pending live evidence and further measurement.


## Native clock and line-oriented edit API

Preferred root prepare is now prepare QUERY SLOT. Native code derives a conservative four-minute deadline from the harness-created baseline commit timestamp (created before the agent loop); missing, expired or future anchors fail. The older explicit-time form remains, capped by the baseline clock when available. The outer harness still independently enforces its budget. No model clock arithmetic is required.

Editors may read current assigned lines with view START END or view A-B, receiving a fresh handle. Unambiguous numeric read packets are accepted. Writes still require an explicit current handle: edit_lines HANDLE CODE_LINE... joins only the supplied line/chunk boundaries, preserving content and spaces. Actual editor status/view replies return an edit_prefix array to extend with code. Ambiguous comma-packed writes are rejected; no code splitting, inferred write fields, backslash unescaping or indentation repair is performed. Optional ranges on the legacy edit form must equal the issued view.

This is a native command grammar and budget calculation, not a host rewrite of malformed SDK calls. Role/slot/hash/compile/verification checks and E4B/token limits are unchanged.


## Source response framing and error status

Role entry responses now begin with a one-line JSON metadata header. When a view is present, raw numbered Python source follows between BEGIN/END V13 SOURCE markers instead of being embedded as a JSON text string inside SDK JSON stdout. This removes an avoidable escaping layer without decoding or repairing generated code. Root delegates intent/slot; editors always read authoritative native status/view before editing. Python physical line slicing uses LF so Unicode separators inside string literals remain content.

Native CLI failure exits nonzero and emits structured metadata on stderr, so the SDK labels failure as error instead of success. Successful views use stdout. Metadata is ASCII-escaped JSON for a stable one-line header; raw source stays UTF-8. Internal transaction dictionaries remain compatible for host callers. SDK/model output and required outer fields are not rewritten.


## Read context versus write authority; explicit location joins

Editor view may now inspect bounded context in its assigned private file outside the editable region. Such replies are read_only and issue no handle/edit prefix. Actual writes remain inside the root-assigned span with a current lease, hashes, compilation and outside/central checks. In-scope narrow still returns a writable view. Another file/slot, outside-file ranges and traversal remain rejected; root still cannot perform editor view actions.

Task IR recognizes single file.py:line / file.py line N addresses and module-qualified global functions, not only classic traceback/class-method forms. An unordered list of stack line numbers is an error unless a complete traceback is present; root must choose the actual innermost location from the unchanged task. Single-letter prose such as article a does not force a loop locus without a code reference. Exact supported loop identifiers retain the restriction.

These native parser/context repairs do not infer model intent, widen write authority or add SDK callbacks. The compiler's closed callback registry and AgentTool schema do not expose a portable child-loop cancellation hook here; native replies cannot guarantee the model stops thinking. No such enforcement is claimed.


## State-derived continuation and root-only finalizer

Root edited-state status now supplies next_execution: the real skill, root-only scripts/finalize.py and one actual current handle. The model must select/send this call; status never applies source. The explicit finalizer program derives the slot from the validated handle and runs the same outside/central checks. Editors do not register it. Generic malformed run.py requests remain errors.

State replies distinguish candidate_applied_to_central=false from applied state. Applied replies advertise submit_patch with empty arguments. Failed-candidate verification is recorded by hash, and status identifies that candidate's owner for the existing one final retry rather than asking a different slot's editor to modify it. No actor prompt is generated and no SDK callback/dispatch is synthesized.

Root now registers run.py plus the fixed-operation finalize.py; editors still register only run.py. No helper asset execution, write authority, model or token/time budget was added. Actual compiled SDK continuation/owner-denial tests and all 313 host tests pass; live completion remains the next gate.

Prepared-state root replies name next_actor=editor_<slot> and root_can_edit=false, with an instruction to check relevance/required alternatives before delegation. There is no edited candidate or finalize/submit continuation yet. This is computed ownership metadata only; the root still chooses the tool call and supplies issue intent.

Verification resolves one repository-bound baseline label/immutable commit ID, shares it through analysis/destructive/locus checks, and reuses original file text only at that object ID within that operation. Working-tree diffs are never cached and the next verification resolves the baseline again. Public baseline labels are unchanged. Real Git regressions cover tag/worktree changes, cross-repository misuse, destructive changes, protected files and nongit fallback. No outside or central check is skipped.

## Exact fragment replacement

Editors additionally register scripts/replace.py. Positional arguments are CURRENT_HANDLE, EXACT_OLD_TEXT, REPLACEMENT_LINE... with no action verb. Status/view publishes replace_execution with the real endpoint and handle; append the exact old fragment and replacement code. The old fragment must have one literal occurrence inside the current view, at most16 physical lines/2048 characters. Zero, overlapping or multiple matches fail unchanged. Replacement elements join with LF; an explicitly empty replacement deletes the fragment. No fuzzy matching, whitespace/escaping repair or automatic indentation occurs. Surrounding source is retained mechanically and the existing locked compile/import/hash/scope/atomic write checks revalidate the edit. Root has no replace.py. Legacy full-view edits remain compatible. Outside/central verification and rollback remain required.

A pressure case also corrects AST analysis of a single leading decoded UTF-8 BOM to match CPython; source bytes are preserved. Double/embedded markers remain invalid. No claim of live task resolution follows from component tests.
