# ADR-013: Publish the prepared assignment owner

Status: Accepted as a correction within the approved role-bound workflow.

Evidence: continuation_run exposed both editor tools throughout. The root nevertheless spent 173 seconds after prepare attempting forbidden edits/finalization before dispatching the owner. The editor accepted an edit at 239 seconds, and the whole run timed out with an empty patch. No verified apply or resolution.

Decision: native root prepared-state replies identify the actual statically bound owner and state that direct root editing is forbidden. Preserve the existing relevance check and BM25 alternative preparation policy; metadata does not create worker prompts, dispatch agents or select a fix. Describe editor tools by their real slot-bound authority. Existing edited/applied continuations and all denial rules stay intact.

Alternative: grant root edits or repair malformed calls. Rejected: erodes the approved authority boundary and disguises protocol failure.

Verification: actual compiled SDK responses for slots 1/2; root edit still denied; no finalizer offered while prepared. Full suite, official validation, unchanged E4B/case/budgets under Seatbelt/subprocess. One frozen-source development trial; task resolution remains separate.
