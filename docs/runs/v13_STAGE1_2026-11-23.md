# v13 Stage 1: native edit execution and tool lifecycle

Status: native component gates pass; live adoption and task-resolution gates NOT met. Candidate remains experimental; v6 is still the frozen measured reference. No subagent dispatch-policy tuning or Kaggle submission occurred.

## What changed

- Task/slot/file/span hashes and single-use edit handles bind edits to the source actually read. Stale, cross-task/cross-slot, replayed and off-assignment requests fail; numbered writes without a handle are refused in managed slots.
- A native prepare operation combines localization, baseline check, workspace creation and numbered assignment. A native finalize operation combines diff/scope/version checks, an independent verification copy, central apply/check and diff analysis. No new harness tools or hidden host argument repair are added.
- Source writes are atomic and fsynced, preserve supported UTF-8/BOM, LF/CRLF, final-newline state and modes. Disposable state uses atomic replacement; lost/old metadata fails closed, including the legacy helper route. Source hashes prevent replay after a lost state checkpoint.
- Outside test failure leaves central unchanged. Central verification failure restores only this transaction's still-matching bytes; concurrent external changes are retained. Managed legacy apply cannot bypass finalization.
- The editor count, BM25 alternative condition, one-final-retry rule, E4B model and token/time budgets remain fixed for this stage. Edit/check work is consolidated; dispatch policy experiments remain deferred.

## Next policy design

The main observed barrier is policy uptake: root has a generic shell tool that bypasses the managed flow. A next design should remove broad shell tools from root/editors and expose distinct native action sets per role through supported ADK skill resources. Script-level permission checks, not role prose, must reject editor prepare/finalize and root edit actions. It must also prevent calling legacy implementation helpers as alternative script entrypoints. SDK source shows executable scripts and readable assets are separately enumerated; role bundle construction and compiler isolation still need verification before any claim of enforcement.

This alone cannot promise to stop premature agent_tool dispatch or submit_patch: those remain official callable tools. Invalid tool-envelope keys also remain model errors. Do not invent timing-based dispatch thresholds until a successful E4B editor and verification lifecycle has been observed.
