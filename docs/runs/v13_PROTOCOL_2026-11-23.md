Experimental development work; no Kaggle submission or promotion. E4B only, official subprocess backend under macOS Seatbelt, no Docker. Four minutes/task, 40 tool calls, 60 turns, 300-second command cap; output 16,384 and thinking 4,096 remain unchanged. ## Evidence and diagnosis

Read-only request capture preserves exact SDK request bytes locally with owner-only permissions and no headers. Full-context generation still chooses wrong skill names or omits required fields: parser correctness on fixed inputs does not establish model tool competence. No SDK patch or model-output cleanup was introduced.

Public primary parser/template sources were opened and ingested into the host-only Edge research library, with hashes and retrieval receipts. No task material, model outputs or private source was ingested. The shard is not packaged for runtime. Sources: [vLLM Gemma parser](https://github.com/vllm-project/vllm/blob/main/vllm/parser/gemma4.py), [native tool template](https://github.com/vllm-project/vllm/blob/main/examples/tool_chat_template_gemma4.jinja).

## Implementation

- Strict typed positional actions and inventory-first skill loading retain required SDK fields and role-bound authority.
- Independent slot copies, per-assignment cache namespaces, durable version markers, actual compilation, protected-file/scope/hash checks, fresh outside verification, central verification and conditional rollback protect edit execution.
- Native conservative baseline-clock deadlines remove model time arithmetic. Explicit line-array edits preserve source bytes without unescaping or reconstructing code.
- Raw numbered source frames avoid redundant JSON source escaping. Structured errors exit nonzero. Bounded context reads issue no outside write lease. Exact file addresses and module-qualified globals improve localization.
- State-derived continuations identify private versus central changes. Root alone registers run.py and finalize.py; editors register only run.py. Prepared state identifies the slot owner. Failed-candidate retry routes to its own editor. No automatic agent dispatch or fabricated worker output.

## Native Git execution result

ADR-014 resolves one immutable baseline ID per verification and reuses successful original-file reads only within that operation. Fresh working-tree diffs, destructive/locus checks, outside verification and central verification are retained. Real Git tests cover tag movement during/across operations, changed source across calls, cross-repository reuse rejection, protected/untracked files, destructive patches and nongit fallback. Final full suite: **317 passed**, zero failures/errors/skips; official validator, asset equality and undefined-name lint pass.

Final fixed-source seven alternating pairs: baseline median **0.155150500 s**, candidate **0.149583292 s**, ratio **0.964117370** (3.59% faster), identical accepted output. Original gate passes without changing its <=10% overhead threshold. Profiling confirms Git subprocess calls drop **8 to 5** per measured verification. Modeled control operations remain **9 to 4**; this does not establish model call reduction. The first benchmark overlapped targeted unit tests and is excluded, with a local receipt; the gate run had tests and inference idle. Earlier failed timing remains above.
