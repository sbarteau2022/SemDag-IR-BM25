# v8 ensemble: smoke preregistration (run_20)

Frozen 2026-11-17, before the run. Status: **PROPOSED**. This is a diagnostic smoke run ("see where we're at"; owner) with no pass/fail gates. Supersedes v7.1 arms A and B. Arm A was rejected because the model cannot count its own tokens, so a prompt allowance means nothing. B's `<|think|>` route is parked.

## Design (owner, 2026-11-17)

`AgenticSubmission/v8_ensemble`, generated by `Tools/v8_ensemble/build_v8.py`:

| Stage | Agents | Output cap | Thinking | Tools |
|---|---|---|---|---|
| 1 | army script `fork.py` + 4 implementers (ParallelAgent), each in its own worktree `.git/wt_k` | 4096 | 3072 | read/edit/run + skill |
| 2 | 4 adversarial reviewers (ParallelAgent), one per candidate; each saves a runnable counterexample | 4096 | 3072 | read + skill |
| 3 | coordinator: `gate.py` = pytest + static typecheck stand-in + code-review rules + counterexamples on every candidate; ranks | 6144 | 4096 | skill |
| 4 | final implementer: `adopt.py` winner into /workspace, fix, last test run (audit), one submit | 6144 | 4096 | read/edit/run/submit + skill |

- vLLM counts thinking inside `max_tokens`, so each thinking budget is set at least 1024 below its cap.
- The sandbox image has no mypy, pyright, pyflakes, pylint or ruff (checked 2026-11-17), so "typecheck" means compile + undefined names + signature and removed-name breaks.
- `eval_config`: 4 min per task, 300 s commands, 100 tool calls and 500 turns (competition defaults).
- Script tests: `tests/test_v8_ensemble.py` (4); full suite 111 passed.

## Environment

- **Subprocess sandbox** under the seatbelt profile, with **no Docker** (owner rule: no Docker unless it is guaranteed not to throttle the Mac).
- oMLX on the competition MLX repack. Parity: thinking budget enforced through the proxy, `top_k` 64 filled when unset (P1), compaction at 14,336.
- Fidelity limits of the subprocess sandbox:
  - test dependencies are not installed;
  - the task package comes from `PYTHONPATH=workspace`, so src-layout repos (requests) would import the host copy.

## Recorded per task

- resolved, failure class, timeout;
- time per stage (implementers, adversaries, coordinator, finalizer);
- tool calls used;
- number of non-empty candidates;
- whether the gate winner equals the candidate that would resolve, when known;
- counterexamples saved and ignored;
- `finish_reason=length` calls by role;
- `submit_patch` count.

## Questions it answers

1. Does the ensemble finish inside 4 minutes, and which stage runs over?
2. How many of the 4 implementers produce a non-empty, unbroken candidate?
3. Does the gate pick a better candidate than a single v7 executor would?
4. Do adversarial counterexamples change any ranking?
